# Popups

How drawn controls open popups (the pickers today; later editable combo boxes and menus). User-facing guide with presenter examples: [SkUiPicker.md](../controls/SkUiPicker.md#popups-on-your-popup-system). Overview: [Architecture.md](Architecture.md#popups).

SkiaUi does not replace navigation, so it ships no pages and no popup windows of its own. A drawn control that needs a popup (the pickers; later editable combo boxes, menus) asks the app's popup system through one abstraction, `ISkUiPopupPresenter`, which the app implements on whatever it uses: MAUI's built-in UI, CommunityToolkit's `Popup`, another popup library, a picker UI of its own, its own overlay.

- **Request.** `ShowAsync(SkUiPopupRequest, CancellationToken)`. The request carries:
  - `Anchor`: the MAUI `View` that opens the popup (the drawn picker; for Core, its `SkUiCoreHost`), from which the presenter finds the window (`Anchor.Window`) and the page to show on.
  - `PlatformAnchor`: the nearest ancestor with a platform view (the surface root). Drawn views have no handler, so presenters that place a popup relative to a view use this one with an offset.
  - `AnchorBounds`: the anchor's rectangle in window coordinates, and relative to `PlatformAnchor`, computed by SkiaUi through drawn offsets, transforms, scrolling and clips (as the semantics tree computes accessibility bounds), with the window's safe area.
  - `Placement`: `Anchored` (below the anchor, above when it fits better, start-aligned and mirrored in RTL, at least the anchor's width), `Window` (aligned in the window by `HorizontalOptions` / `VerticalOptions`: a centered dialog or a bottom sheet), `Absolute` (a window rectangle from the app) or `BottomPane` (docked to the window's bottom edge, edge to edge, as iOS's picker). The space on each side of the anchor is precomputed, so a presenter flips without measuring.
  - Size: `PreferredSize` (the content measured), `MaximumSize` (the window's safe area minus margins, `MaxPopupHeight`).
  - `Content`: a ready MAUI `View`, a drawn surface (`SkUiContentView`) with the list, which any popup system hosts like any other view. A presenter that shows its own UI instead reads the typed request (`SkUiListPopupRequest`: item texts, selected index, title) and completes it with its choice.
- **Lifetime.** `ShowAsync` completes when the popup is gone. The content completes the request with a result (an item chosen); the presenter completes it with none when the user dismisses it (a tap outside, Back, Escape); the control cancels the token when the popup must close (`IsOpen = false`, the picker unfocused, disabled, hidden or removed, the anchor scrolled or the window resized). One popup per control; the request, its content and the presenter keep no reference to the control after completion.
- **Registration.** App-wide (`SkUiPopups.Presenter`, also settable from `UseSkiaUi(options => options.PopupPresenter = …)`), overridable per control (`PopupPresenter`). With none registered, pickers fall back to MAUI's own `DisplayActionSheetAsync` on the anchor's page (`SkUiActionSheetPopupPresenter`: centered, plain item texts; MAUI's UI, not SkiaUi's) and write one `Trace` line.
- **Closing.** The token passed to `ShowAsync` is the request's `CloseRequested`: the content's choice (`Complete`) and the control's close both cancel it, so a presenter has one rule (close on cancellation). The request holds the anchor, surface, page and window weakly and drops the content when it completes; a picker also closes its popup when its surface is torn down, so a presenter's popup still open after its page went keeps nothing alive. Presenters shown in the docs: CommunityToolkit (compiled, in the samples app and the demo), MAUI's action sheet (built in), a popup control of the app's (a sketch), a navigation service of the app's with a popup stack (open, close, bring to front).
- **Presenters are not in the library.** The library takes no popup dependency. Integrations ship as their own packages (below); other presenters are shown in the docs. The samples app and the control docs carry presenters for MAUI's action sheet, CommunityToolkit's `Popup` (the content placed in the toolkit's overlay by alignment and margins, since toolkit v2 has no anchor); [Migration.md](../Migration.md) and the migration skills show how to plug in the app's own.
- **Native over drawn.** The popup is a window-level platform view of the app's popup system, so it covers hosted native controls without overlay masks.

## Integration packages

`SkiaUi.Maui` depends on MAUI and SkiaSharp only. Integrations with other libraries are packages of their own, released with it (same version, one changelog) and built on its **public API** only (no `InternalsVisibleTo`), so they cannot couple to internals and show what app authors can build themselves:

- **SkiaUi.Maui.CommunityToolkit** (`MauiSkiaUi.CommunityToolkit/`): the popup presenter on the toolkit's `Popup`. Planned ([roadmap](Roadmap.md)): drawn counterparts of the toolkit's `UniformItemsLayout` and `DockLayout` on its public layout managers (`UniformItemsLayoutManager`, `DockLayoutManager`), as `SkUiFlexLayout` runs MAUI's `FlexLayoutManager`. Needs one extension point made public first: `SkUiLayout.AffectsChildLayout` (a child's attached property, e.g. `DockLayout.DockPosition`, re-measures the layout) and `OnChildrenChanged` are `private protected` today.
- A package per further popup library only if asked for; until then, a docs sketch.
