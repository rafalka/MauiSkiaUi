# SkiaUi 1.18 implementation plan: the sheet and the time-clock screen set

**Goal:** the review's in-surface sheet (F3) and chips (F5), custom tab headers (placed here on 25 November 2026), and the nine feature requests filed from one real screen set (employee self-service: time clock, breaks, balances, shifts), issues [#128](https://github.com/rafalka/MauiSkiaUi/issues/128) to [#136](https://github.com/rafalka/MauiSkiaUi/issues/136). Each request was checked against the architecture and the code before it was taken in ([review](#review-of-the-requests)).

**Status:** released in 1.18.0 (27 November 2026); device checks left open are on the [verification backlog](../design/Roadmap.md#verification-backlog). Before release: proposed 26 November 2026; the decisions below are to be agreed before their phase starts. Phase A built on `1.18-implementation` (26 November 2026): A1 font features, A2 press scale, A3 swipe view groups, A4 hit slop, each with its tests (`FontFeatureTests`, `PressScaleTests`, `SwipeViewTests`, `HitSlopTests`), docs and changelog; the benches and gallery pages are open. Phase T built 27 November 2026. Where the build differs from the plan, the phase's notes below say so.

## Review of the requests

All nine are valid, fit the two-layer, retained-rendering architecture, and need no change to it. Where the request and the code or an existing brief disagree, the plan follows the decision named in the last column.

## Decisions

Proposed 26 November 2026.

- **D1 1.18 scope.** The sheet (F3), chips (F5), custom tab headers and requests #128 to #135. F5 comes into 1.18 (the 1.17 plan's D1 left its release to this plan) because a real screen needs it and its brief is ready; range slider and rating (F6) stay on the backlog.
- **D2 Press scale is a property, not a `PressFeedback` value.** `PressedScale` (`double`, default `-1`: the look's `SkUiLook.PressedScale`, which is `1`, no scale, in every built-in look) on `SkUiView` and `SetPressedScale` on Core nodes, combinable with `Overlay` and `Fade`. A composite-time scale around the centre, driven by the pressed animator as `Fade` is (no re-record); length and easing are the look's press transition, not per-control properties. A press that turns into a scroll springs back with the pressed state. Reduce motion: no scale. The migration docs and skill convert Community Toolkit `TouchBehavior.PressedScale`.
- **D3 Hit slop.** `HitSlop` (`Thickness`) on `SkUiView`, `SetHitSlop` on Core nodes; extends hit-testing only, never layout or drawing. `MinimumTouchTargetSize` (`double`, default `0`) grows the hit area symmetrically up to that size; the look default stays `0` so existing apps do not change.
  - **Exact hits win:** the router searches without slops first, and only when no participant is found searches again with them, so a slop never steals a tap from a neighbour under the finger. Between two slops the topmost wins.
  - **Ancestors let the search in:** arrange computes how far a subtree's slops reach past each node's rectangle (render props carry it, zero and skipped when no slop is set), and `FindTarget` uses that inflated rectangle for ancestors that do not clip. Slops are clipped by the nearest children clip (a scroller's viewport) and the surface.
  - **Semantics** frames grow the same way, clipped the same way. The headless pointer benches stay within noise when no slop is set.
- **D4 Font features.** `FontFeatures` on `SkUiLabel`, `SkUiSpan`, the buttons, `SkUiEntry`, `SkUiEditor` and their Core twins, typed: an immutable `SkUiFontFeatures` list (value equality, a collection expression in code) of `SkUiFontFeature`s (a checked tag and a value, named members for the common features, `StylisticSet(n)`, `CharacterVariant(n)`, `.Disabled`), with a type converter for CSS-like text in XAML and styles (`"tnum, -liga, ss01"`) `SupportedBy(fontFamily)` listing a font's features (its GSUB and GPOS feature lists), and `Describe(tag)` / `Known` giving each registered feature a name, a description and its default (`SkUiFontFeatureInfo`). First built as a `string` property; changed before release so features are discoverable in code and checked when written, not parsed. The list joins `SkUiTextStyle`, so it is part of every text cache key. Passed to HarfBuzz when shaping; a style with features skips the simple Latin path. Fonts without a feature draw as before. MAUI's bindings do not run type converters: a view model binds an `SkUiFontFeatures`, not text.
- **D5 Live regions.**
  - `SkUiAccessibility.LiveRegion` (attached, `SkUiLiveRegion`: `None`, `Polite`, `Assertive`) on `SkUiView`; `SetLiveRegion` on Core nodes.
  - Built on the semantics owner's change report: a node with a region whose spoken text (name and value) differs from what was last read for it, and that is shown, is read. Coalesced per node (the last text within 300 ms). Nothing is read while the node is hidden, off screen or outside the topmost modal pane. A node that appears with a region set is read once.
  - Android: the virtual node's live region and `TYPE_WINDOW_CONTENT_CHANGED` with `CONTENT_CHANGE_TYPE_TEXT`. Apple: an announcement, queued when polite. Windows: the peer's `LiveSetting` and `LiveRegionChanged`.
  - `SkUiAccessibility.Announce(anchor, text, politeness)` reads text tied to no element; on Android through a hidden live-region node of the anchor's surface.
  - `SkUiAccessibility.UpdatesFrequently` (attached) and `SetUpdatesFrequently`: the iOS trait (today set only for progress bars), and on Android the state description updates without an announcement.
  - Nothing is computed while no screen reader runs (the semantics tree is built lazily).
- **D6 Progress ring:** `SkUiProgressRing` and `SkUiCoreProgressRing`, shaped like the progress bar: `Progress`, `ProgressTo`, `IsIndeterminate` (the activity indicator's render-thread rotation), `ProgressColor`, `TrackColor`, `Thickness` (DIPs, `-1` the look's), `StartAngle` (`-90`), `IsClockwise`, `LineCap` (`Round`, `Butt`). `Content` (SkUi\*: a view; Core: a child node) is laid out in the square inscribed in the inner circle. Drawn by a new look member `DrawProgressRing(canvas, SkUiProgressRingPaint)` next to `DrawProgressBar`. Semantics as a progress bar. A segmented ring, donut and gauges are F4.
- **D7 Stacked bar:** `SkUiStackedBar` and `SkUiCoreStackedBar`. `Segments`: SkUi\* a collection of `SkUiBarSegment` (bindable: `Value`, `Color`, `Label`), Core a list of `SkUiBarValue(Value, Color, Label)`. `Maximum` (`-1`: the sum), negative values count as `0`, `SegmentSpacing`, `CornerRadius` (the bar's outer ends; `-1` the look's), `TrackColor` for what is left up to `Maximum`. Changes animate by tweening every value with the progress tween; reduce motion jumps. Semantics: one element whose value lists the labelled parts. No `ItemsSource` with paths in 1.18 ([Not in 1.18](#not-in-118)); the legend stays app layout.
- **D8 Swipe view.**
  - `SkUiSwipeView.ExclusiveGroup` (`string?`, default `null`): when a view of a group starts opening (swipe or `Open`), the other open views of that group on the same surface close, animated.
  - `SkUiCollectionView.CloseSwipeViews(bool animated = true)` closes the open swipe views among its realized rows.
  - `CloseAsync(bool animated = true)` completes when the content is back.
  - The swipe items of a row become custom actions of the row (as reorderable items have theirs), so a screen reader reaches "Remove" without the gesture.
  - No new open/close events: `SwipeStarted` and `SwipeEnded.IsOpen` are MAUI's and cover them; the docs say so.
- **D9 Chips follow the F5 brief** ([ImplementationPlan-PerformanceAndControls.md](../design/ImplementationPlan-PerformanceAndControls.md#f5-chips)), keeping its names: `IsSelected` matches `SelectedItem` / `SelectedItems` and the pickers; `Wraps="False"` is the scrolling row. From the request: `Padding` on the group (the scrolling row's edge insets, scrolled with the chips) and `BadgeText` on a chip (the count), drawn by the look's tab badge painter from 1.17.
- **D10 The sheet follows the F3 brief** ([ImplementationPlan-PerformanceAndControls.md](../design/ImplementationPlan-PerformanceAndControls.md#f3-in-surface-sheet), D5 there: a drawn container inside a surface, not a window), with these additions:
  - **`Presentation`** (`SkUiSheetPresentation`: `Sheet`, `Dialog`, `Auto`; default `Sheet`): `Dialog` is a centred card at most `MaximumWidth` wide (the look's), with no detents or drag; `Auto` is a sheet on compact widths and a dialog (the tablet form sheet) above the look's breakpoint.
  - **Header and actions:** `Title`, `Description` and an `Actions` view slot, drawn with `SkUiPopupParts`' title and button row so a picker opened in a sheet looks like the others.
  - **Stacking:** several sheets can be open; the last opened is on top; Back, Escape and a scrim tap close the topmost; only the topmost is a modal pane.
  - **`SkUiSheet.ShowAsync<TResult>(anchor, content, configure)`** opens a sheet on the anchor's surface root and completes with the value passed to `Close(result)`, or `default` when dismissed. It needs an overlay layer on the surface root (internal), which `SkUiSheetPopupPresenter` uses too: step S1 decides its shape.
  - **No Core twin in 1.18.** A sheet has to be on the surface root to cover the page; a Core tree lives inside an `SkUiCoreHost`. Core content goes into a sheet through a host.
  - **Accessibility:** the modal pane (focus moves in and is trapped, the page behind leaves the tree, the title is read as the pane title); `AutomationId`s on the scrim and the grabber.
  - **Limits** in the docs: inside one surface, so it cannot cover hosted native views (overlay masks, backlog) or native chrome outside the surface (a Shell tab bar); it covers a drawn bottom bar in the same surface.
- **D11 Custom tab headers** as placed on the [roadmap](../design/Roadmap.md#1180-the-sheet-chips-tab-headers-and-the-time-clock-screen-set-shipped); its open questions are decided in step T1.
- **D12 Release:** `1.18.0`. Cut line: phase T (tab headers) moves to 1.19 if the sheet runs long; the other phases ship together.

## Phase A: small pieces (parallel, in worktrees)

Independent of each other; each one appends to the look and the gallery, merged in order.

- **A1 Font features (#132, S).** `SkUiFontFeature` and `SkUiFontFeatures` (parser, converter, `SupportedBy`); `SkUiTextStyle` member; `SkUiShaping` passes features and skips the simple path; spans in `SkUiRichTextLayout`; the edit layout. *Check:* `FontFeatureTests` (Lobster's ligatures and kerning change widths and Roboto Mono's small capitals its glyphs, as no bundled font has `tnum`; cache keys differ; tags checked when written; text form in XAML and styles; `SupportedBy`); `core-labels`, `skui-labels` within noise.
- **A2 Press scale (#133, S).** Look member, `PressedScale` on both layers, the animator's scale channel, reduce motion. Built: shown whenever a view is pressed (buttons and toggles too), not only with `ShowsPressEffect`, as a composite-time `SkUiRenderProps.PressScale` applied only to the drawn matrix (`DrawnMatrix`); hit-testing keeps the unpressed size. *Check:* `PressScaleTests` (scale reaches the value and comes back; cancelled by a scroll; no re-record while pressed); `ImplicitStyleTests`.
- **A3 Swipe view (#135, S).** `ExclusiveGroup`, `CloseAsync`, `CloseSwipeViews`, custom actions. *Check:* `SwipeViewTests` additions; a leak scenario that opens rows of a group and scrolls them away.
- **A4 Hit slop (#134, M).** Built differently from D3's ancestor reach: `FindTarget` is unchanged. Nodes with a slop are tracked weakly per UI thread (`SkUiHitSlop`); only while one exists, the press looks for the node whose slop holds the point after the ordinary search, mapped through `MapInsideClips` (so its ancestors' clips cut it), and takes it when the search found nothing there or an ancestor of it; the nearest of several wins. Taps accept a release inside the slop; semantics frames grow. `MinimumTouchTargetSize`. *Check:* `HitSlopTests` (slop past a non-clipping parent; clipped by a scroller; exact hit wins over a neighbour's slop; disabled node blocks inside its slop); pointer benches within noise.

## Phase P: progress (#128, #129)

- **P1** Look: `SkUiProgressRingPaint`, `DrawProgressRing` in the default and platform looks. **P2** `SkUiProgressRing` with content. **P3** `SkUiCoreProgressRing`, pixel comparison with P2. **P4** `SkUiStackedBar` and `SkUiCoreStackedBar` on a shared internal segments model. *Check:* `ProgressRingTests`, `StackedBarTests`, semantics values, `ImplicitStyleTests`; a `skui-rings` bench (200 animating rings).
- *Built* on `1.18-plk` (26 November 2026). The rings are content views (`SkUiContentView`, `SkUiCoreContentView`), so `Content`, `ContentTemplate` and `Padding` come with them. `LineCap` is MAUI's `PenLineCap` (`Round`, `Flat`, `Square`) rather than a new enum; the direction ignores right-to-left. Indeterminate rings record nothing for `Progress` changes; their background turns with the arc (documented). Look: `DefaultProgressRingSize` (Fluent 32), `ProgressRingThickness`, `IndeterminateProgressRingSweep` / `Period`, `ProgressRingGap` (Material 3: 4). The stacked bar animates with a new look transition, `SkUiTransitionKind.StackedBar` (250 ms; reduce motion and a look's `None` jump), rather than `ProgressTo`'s tween, so a look can tune or turn it off; `SegmentSpacing` also takes `-1` for the look's (`StackedBarSegmentSpacing`, Material 3: 4). Look members `DrawStackedBar` / `SkUiStackedBarPaint` with `SkUiStackedBarPart`s. Gallery: `ProgressRingDemoPage`, `StackedBarDemoPage`, `CoreProgressRingDemoPage`. Bench `skui-rings` (200 rings, half indeterminate; the ring is created by name so baselines without it build).

## Phase L: live regions (#131, M)

- **L1** API and the change detection on the semantics owner (platform-neutral, headless-testable through a recording platform sink). **L2** Android, **L3** Apple, **L4** Windows. **L5** `Announce` and `UpdatesFrequently`. *Check:* `LiveRegionTests` (coalescing, hidden and off-screen nodes, appearing nodes, modal pane); device checks with TalkBack, VoiceOver and Narrator on the verification backlog.
- *Built* on `1.18-plk` (26 November 2026). The platform sink is an owner event, `SkUiSemanticsOwner.Announcement` (the element or none, the text, the politeness); tests drive the report and read timers with `Flush(now)` / `ReadDueLiveRegions(now)`. A region on a container passes to the elements inside, and a live text absorbed into an actionable group makes the group live. The modal pane is not tested yet: no drawn modal pane exists before phase S, whose pane takes the page out of the tree, which is what keeps it from being read. Android: a live element's change is held back while its text waits and then reported once with `CONTENT_CHANGE_TYPE_TEXT`; `Announce`'s hidden node stays listed for 3 s; `UpdatesFrequently` is a throttle (one report a second), as Android has no "update without announcing". Windows `Announce` is a notification event of the surface's peer. All four platform heads compile (Windows on macOS, as [Accessibility.md](../design/Accessibility.md#verification) says); the screen readers themselves are on the verification backlog.

## Phase S: the sheet (F3, #136, L)

The brief's steps, with D10's additions placed:

- **S1** Control page; the surface root's overlay layer. **S2** `SkUiSheetEngine` (detents, nearest detent by position and velocity, dismissal). **S3** Look members and `SkUiSheet` with `IsOpen`, detents as render-thread translation, `Presentation`. **S4** Drag and the nested-scroll hand-off. **S5** Modal behaviour (scrim linked to the position through 1.16's links, focus trap, Back and Escape), stacking. **S6** Header and actions slots; `ShowAsync<TResult>`. **S7** `SkUiSheetPopupPresenter`. **S8** Leak scenario `SheetOpenedAndClosed`, gallery page with the request's cases (confirm dialog, option list, action sheet with a destructive row, form with a time picker).
- *Checks:* as in the brief, plus `SheetStackTests` and `SheetResultTests`.
- *Built* on `1.18-sheet` (27 November 2026). **S1:** the overlay layer is an internal full-size view of the surface root (`SkUiSurfaceOverlay`, `SkUiView.SurfaceOverlay`), listed last among the root's drawn children (so drawing, hit-testing, semantics and focus see it) and arranged in the root's frame after its content; the walks that start at a root (animation clock, native views, what shows) include it. **S2:** `SkUiSheetEngine` resolves detents (a height adds the bottom inset, fit includes it) and picks the resting place: below the fling speed the nearest detent or closed, faster the detent that way nearest the fling's projection. **S3–S4:** the sheet's position is the offset of an internal `SkUiScrollView` (the track) whose content is the sheet's length past a viewport of nothing, so drags, flings, the springs to detents (the controller's new `SnapTargetResolver`) and the nested-scroll hand-off are the scroll views'; code moves use the controller's new tween with the look's `Sheet` transition. The track takes pointers only over the panel (`ISkUiInputNode.HitsSelfAt`, new, read after the children). A dialog is the same panel centered, faded with `AnimateFromAsync`. Side sheets measure their detents along their width and default to one full detent. **S5:** the scrim links its opacity to the track's offset (1.16's links); the modal pane is the root's (`ModalPane`), registered once the sheet is laid out open (XAML and bindings may open it before it is placed); Back is an `OnBackPressedCallback` per open modal sheet. Outer scrollers the user cannot drag no longer take handed-over drags (`IsUserScrollEnabled`), so a sheet with `IsDragEnabled="False"` stays put under a list. **S6:** the header is `SkUiPopupParts.Title` and a muted description; the actions are padded as the popup button row. **S7:** the presenter keeps the content's measured height and takes the sheet's width. Tests: `SheetEngineTests`, `SheetTests`, `SheetStackTests`, `SheetResultTests`, `SheetPopupPresenterTests`; leak scenario `SheetOpenedAndClosed`; gallery `SheetDemoPage`. Not done: a platform pane title, VoiceOver's escape gesture. *After the first device check (27 November 2026):* the overlay layer reset its render nodes when it emptied (a later `ShowAsync` sheet was open but not drawn); an open placed sheet is drawn on the overlay layer in open order (`SkUiView.RenderHost`, the layer's `Shown`), so a sheet placed earlier or inside another sheet opens over the open one instead of under it (`SheetStackTests`, `SheetPopupPresenterTests`; the gallery opens a sheet and a dialog from sheets).

## Phase K: chips (F5, #130, S to M)

The brief's seven steps, with D9's `Padding` and `BadgeText`. *Check:* `ChipTests`, `ChipGroupTests`, bench `skui-chips` (500 chips).

*Built* on `1.18-plk` (26 November 2026). Chips derive from the buttons (`SkUiChip : SkUiButton`, `SkUiCoreChip : SkUiCoreButton`), so text, font, image, command, press, focus and hit slop come with them; the labels got a `ChromeInset` hook (zero for labels and buttons) for the room of the check, badge and × inside the padding. The look has `DrawChip` / `SkUiChipPaint` and sizes (`DefaultChipHeight`, `DefaultChipPadding`, `DefaultChipCornerRadius`, `ChipIconSize`, `ChipIconSpacing`, `ChipStrokeWidth`) but no `MeasureChip`: a chip measures as a button, at least `DefaultChipHeight` high. The badge is an inline pill before the × (the 1.17 tab badge is not a look member), with its own colors and font (`BadgeColor`, `BadgeTextColor`, `BadgeFontSize` with the look's `ChipBadgeFontSize`, `BadgeFontFamily`, `BadgeFontAttributes`); its text layout is invalidated when the text changes (an `SkUiTextLayout` keeps lines by style and width, not by text). `ShowsRemoveButton`'s default for input chips is read with `IsSet`, so clearing it goes back to the kind's. A selected filter chip with an image shows no check. The selected look beyond `SelectedColor` is the `Selected` state of `CommonStates` (`SkUiView.IsInSelectedVisualState`, shared with selected collection items), not a `Selected*` property per value; Core chips raise `PropertyChanged` for `IsSelected`. In `Single` mode tapping the selected chip clears it. A group's chips take their item as binding context and `CommandParameter`; there is no chip template, and the app removes items on `ChipRemoved`. Leak scenario `ChipsShown`; gallery `ChipsDemoPage`, `ChipGroupDemoPage`, `CoreChipsDemoPage`; bench `skui-chips` (500 chips; created by name for baselines). The pickers' token display still draws its own tokens (roadmap note).

## Phase T: custom tab headers (M, cut line)

- **T1** Decide the roadmap's open questions (measuring in equal and content widths, what the header takes over from the look, the indicator's bounds, semantics). **T2** `SkUiTabView`. **T3** `SkUiCoreTabView` (header node or factory).
- *Built* 27 November 2026. **T1** decisions in [SkUiTabView.md](../controls/SkUiTabView.md#custom-header-decisions-118-t1): a `DataTemplate` on the tab view (every tab; a selector chooses by the tab) and on the tab item (one tab, winning), no view property; the binding context is the tab item, which gets read-only `IsSelected` and `CurrentTextColor` (the look's text color for the tab's state, the tab view's colors over it), and the view's root is in the `Selected` / `Disabled` visual states. Content widths take the view's measured width with no look padding; equal widths share the strip; the strip is at least the look's height. The look keeps the strip and the indicator (its label width, where a look uses one, is the view's) and draws nothing else for that tab. The view is excluded from semantics with its subtree, input-transparent (taps select the tab) and takes no focus: the header stays one strip part read from `Header`. **T2–T3:** the shared strip model measures and arranges the views through the strip node (`ISkUiTabHeaderHost`); each layer's strip hosts them in cells over the indicator. Core: `SkUiCoreTabItem.HeaderContent` and `SkUiCoreTabView.HeaderFactory` (called once per tab and factory; `null` keeps the look's header), `IsSelected` / `CurrentTextColor` through `PropertyChanged`. *Check:* `TabHeaderTests` (both layers, pixel parity right to left); the leak scenarios `TabViewSwiped` and `CoreTabViewSwiped` now include header views from a template / factory and a tab's own, removed and replaced; gallery: a "Headers" editor on `TabViewDemoPage`, "Header nodes" on `CoreTabViewDemoPage`.
