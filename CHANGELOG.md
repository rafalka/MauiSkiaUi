# Changelog

Release notes for the NuGet package **SkiaUi.Maui**.

Add entries under `## Unreleased`, grouped under these subsections (only the ones that have entries, in this order):

- `### New features`: one bullet per feature, led by a bold title (`- **Title:** details`); nested bullets for the details.
- `### Breaking changes`: what callers must change, one bullet each.
- `### Fixes`
- `### Other`: behavior changes that are not breaking, performance, samples and demo.

Publishing (the NuGet publish workflow, [docs/Releasing.md](docs/Releasing.md)) renames `## Unreleased` to the new version. The package's `PackageReleaseNotes`, shown on nuget.org as plain text, gets a link to the version's section, the titles of its new features and its breaking changes; the GitHub release gets the whole section. Newest section first; headings are exactly `## <version>`. Sections up to 1.0.0-Prerelease07 predate the subsections.

## Unreleased

### New features

- **A cache key per image view:** `CacheKey` on `SkUiImage` and `SkUiImageButton` (bindable, `SetCacheKey`) and on `SkUiCoreImage` (FFImageLoading's). It is the cache identity of that view's source, in place of `SkUiImageCache.CacheKeyFactory` and the source's own key: views with one key share the decoded image and the download whatever their sources (signed URLs, stream sources, which are otherwise not cached). `SkUiImageCache.RemoveByKeyAsync(key)` forgets what is cached under a view's or the factory's key ([doc](docs/controls/SkUiImage.md#a-key-per-view)).
- **Downsampling to the view's size:** `DownsampleToViewSize` on `SkUiImage` and `SkUiImageButton` (bindable, `SetDownsampleToViewSize`) and on `SkUiCoreImage` (FFImageLoading's). A new source loads at the view's next arrange and decodes no larger than the arranged size (fitting, or covering for `AspectFill` / `Fill`), in steps of 16 DIPs so rows of one size share cache entries; a larger arrange decodes again, a smaller one keeps the image. Dimensions the view takes from its image are not bounded, and explicit `DownsampleWidth` / `DownsampleHeight` win ([doc](docs/controls/SkUiImage.md#key-properties)).
- **Image download progress:** `LoadingProgress` (read-only bindable on `SkUiImage` / `SkUiImageButton`, a property on `SkUiCoreImage`) and the `DownloadProgress` event (`SkUiImageDownloadProgressEventArgs`: bytes received, total, fraction; FFImageLoading's). The fraction of a URI download received, -1 without a `Content-Length`, 1 once shown; reports are coalesced per dispatcher turn and reach every view waiting for the same download ([doc](docs/controls/SkUiImage.md#download-progress)).
- **Image fade-in:** `FadeAnimationEnabled`, `FadeAnimationDuration` and `FadeAnimationForCachedImages` on `SkUiImage` / `SkUiImageButton` (bindable, `SetFadeAnimation`, `SetFadeAnimationForCachedImages`) and `SkUiCoreImage` (FFImageLoading's; off by default). A loaded image fades in over its placeholder on the render thread, with the look's new `SkUiTransitionKind.ImageFadeIn` (200 ms in `DefaultSkUiLook`); memory-cache hits, images loaded before the view was drawn and images replacing a shown one show at once, and nothing fades under reduced motion ([doc](docs/controls/SkUiImage.md#fade-in)).
- **Android XML drawables in images:** on Android a file source that names a drawable defined in XML (a vector, a shape, a layer list) is drawn by Android, at its intrinsic size or at the decode bounds (sharp in a larger view), as MAUI's `Image` shows it; before, it failed to decode ([doc](docs/controls/SkUiImage.md#android-xml-drawables)).

### Fixes

- **Radio buttons are as wide as MAUI's on iOS and Mac Catalyst:** `IosSkUiLook.RadioButtonPadding` is 7 on every side (was 8 × 7), measured on iOS 26: MAUI's template lays out 41 pt around its text. A radio button with text was 2 DIPs wider than MAUI's.
- **Android (Material 2) progress bars have square ends,** as MAUI's: `AndroidSkUiLook.GetProgressBarCornerRadius` returns 0 (the Material 3 look keeps its round ends). Measured against MAUI 10.0.120 on Android (Material 2 and 3), iOS 26 and Mac Catalyst, where the bars' heights already matched.
- **Popup frames from the look:** `SkUiLook.GetPopupCornerRadius(placement)` and `GetPopupShadow(placement)`, passed to presenters as `SkUiPopupRequest.CornerRadius` and `Shadow`; the drawn popup content is clipped to the corners. The Android looks match the platform's picker dialog: 4 dp (Material 2), 28 dp for window popups and 4 dp at a field (Material 3); other looks keep 10 and the soft shadow `SkUiToolkitPopupPresenter` used. The toolkit presenter takes the request's frame unless its own `CornerRadius` / `Shadow` are set (their defaults are now `NaN` / unset, for the look's).

### Other

- Benchmarks: `skui-images` and `core-images` (1,000 images of eight photos in a grid) and their `-viewsized` variants with `DownsampleToViewSize`.
- Demo: an Android vector drawable on the image page (Android only), next to MAUI's `Image`.
- Leak scenario `ImageFadingIn`: images and a Core image fading in, some removed mid-fade, the page closed while others fade.

## 1.3.0

### New features

- **`RunsTappedCommand`** (protected virtual on `SkUiView`, default `true`): a host that hands its `TappedCommand` and `TappedCommandParameter` to the node it draws (a Core node with `ShowsPressEffect`) returns `false`. That node is then the one tap target, screen reader element and keyboard focus stop, and the host no longer runs the command as well. Before, such a wrapper was two nested buttons with the same `AutomationId`, read twice and stopped on twice by Tab (#63).
- **`PressFeedback`** (`SkUiView` and `SkUiCoreNode`, with `SkUiPressFeedback`): how `ShowsPressEffect` shows the press. `Overlay` (default) is the look's dim or ripple, as before. `Fade` draws no overlay and fades the view and its children to the look's new `PressedContentOpacity` (0.4) with the press and release transitions, as iOS icon buttons do: a dark glyph button the dark tint hardly changed now shows its press (#64).
  - The fade is composited: its frames re-record nothing, and it multiplies `Opacity`, so an opacity animation and the fade do not affect each other.
- **`DefaultMinimumHeight`** (protected virtual on `SkUiButton` and `SkUiCoreButton`): the minimum height used while none is set, the look's `DefaultButtonMinimumHeight` by default. A subclass gives its own size of button, as with `DefaultCornerRadius` and `DefaultPadding`, without a `MinimumHeightRequest` that every call-site style would have to repeat; a set minimum still wins (#65).
- **`SkUiDisplayBinding`**: reads items' texts through an `ItemDisplayBinding`-style binding (`ToString()` without one), `GetText(item)` and `GetTexts(items)`, applying the binding only while reading, so neither it nor the binding keeps the last item alive and readers and pickers can share one binding instance (also after a read that threw). For own controls that show items as text (chips, tags, lists); `SkUiPicker` and `SkUiPickerColumn` now use it (#66).
- **`SkUiDragger` and `SkUiCoreDragger`:** a drawn handle that reports drags and leaves the handling to the app ([docs](docs/controls/SkUiDragger.md)).
  - `DragStarted`, `DragDelta`, `DragCompleted` with `SkUiDragEventArgs` (`TotalX` / `TotalY`, `DeltaX` / `DeltaY`, `IsKeyboard`, `IsCanceled`), measured in the parent's coordinates: a handler that moves or resizes the dragger itself still gets totals that follow the pointer. Subclasses override `OnDragStarted` / `OnDragDelta` / `OnDragCompleted`, `EffectiveDragAxis` and `CanDrag`.
  - `DragAxis` (`SkUiPanAxis`: `Both`, `Horizontal`, `Vertical`); arrow keys are drags of `KeyboardIncrement` (10 DIPs).
  - Drawn by the look: an optional line along it (`ShowsLine`, `LineColor`) and a grip (`ShowsGrip`, `GripColor`, `GripAlignment`: start, center, end or fill, `GripLength`). `SkUiLook.DrawDragger` (`DraggerPainter`, `SkUiDraggerPaint`), `DefaultDraggerThickness`, `DraggerGripLength`, `DraggerGripThickness`, `DraggerGripInset`, `DraggerLineThickness`.
  - Thin draggers: the touch area is at least `TouchThickness` across (default: the look's `DraggerTouchThickness`, 24 DIPs), centered on the dragger, so a 1 DIP splitter (`HeightRequest="1"`) takes no room in the layout and is still easy to grab. The touch area and the grip reach over the neighbors, drawn unclipped; put the dragger after them so it is on top. `SkUiDraggerPaint.TouchBounds` tells a painter where it may draw.
- **`SkUiGridSplitter` and `SkUiCoreGridSplitter`:** draggers that resize the rows or columns of the grid they are in ([docs](docs/controls/SkUiGridSplitter.md)). MAUI has no splitter; the model is the `GridSplitter` of WPF, Avalonia and WinUI.
  - `ResizeBehavior` (`SkUiGridResizeBehavior`): the tracks around a splitter in a track of its own, the splitter's track and the next one (a splitter at the end of a cell), the previous one and its own, or its own alone; by default from its alignment. Two star tracks get new weights in the new proportion, next to a star track the other one becomes absolute, `Auto` and absolute tracks become absolute. `ResizeDirection` (`SkUiGridResizeDirection`: `Auto`, `Columns`, `Rows`).
  - Works in a `SkUiGrid` and, as a surface of its own, in MAUI's `Grid`; the Core splitter in a `SkUiCoreGrid` and a `SkUiCoreTable`: resizable columns with grips in the header cells. A splitter spanning the table's rows merges no cells, so the row separators still cross it.
  - Limits: `SkUiGridSplitter.MinimumLength` / `MaximumLength` attached to MAUI row and column definitions; the Core definitions' `MinHeight` / `MaxHeight` (`MinWidth` / `MaxWidth`).
  - Keyboard focus, arrow keys, and a slider for screen readers over the size of the first track.
- **Reordering items in `SkUiCollectionView`:** MAUI's `CanReorderItems`, `CanMixGroups` and `ReorderCompleted`, in lists and grids, vertical and horizontal, grouped or not.
  - A touch or pen lifts an item with a long press, the mouse with a press and drag. A copy of the item follows the pointer, scaled and shadowed by the look, and the items it passes move aside on the render thread. Held near either end, the list scrolls.
  - On release, the item leaves its list (`RemoveAt`) and goes to its new place (`Insert`), as MAUI's handlers move it, then `ReorderCompleted` is raised. The item stays selected and the list keeps its scroll offset. Lists that do not notify are moved too and shown in their new order. The source (or the group) must be an `IList` that is neither read-only nor fixed-size.
  - In grouped lists, items stay in their own group unless `CanMixGroups` is set. Collapsed groups take no items, and group headers and footers stay where they are.
  - Screen readers offer "Move up" and "Move down" on each item that can move ("Move left" / "Move right" where one place is sideways), on TalkBack and VoiceOver. The texts are `SkUiStrings.MoveUpText`, `MoveDownText`, `MoveLeftText` and `MoveRightText`.
  - The look sets the lift (`ReorderLiftScale`, `GetReorderLiftShadow()`, the `ReorderLift` and `ReorderMove` transitions) and the auto-scroll (`ReorderAutoScrollZone`, `ReorderAutoScrollSpeed`).

### Fixes

- **Blank drawn view under a hidden ancestor (#69):** a software-drawn view (`HwAccelerated = false`: labels, buttons, `SkUiCoreHost`; every drawn view on Windows) whose handler was created while an ancestor was hidden (`IsVisible="False"` on a container, a lazily applied template, a page body shown after loading) stayed blank once the ancestor was shown, on MAUI 10.0.120 and later. The internal SkiaSharp view no longer has a MAUI parent, so it inherits nothing from the root's ancestors that could go stale: the root's native view shows and hides it, and the drawn views handle `IsEnabled` themselves (as on GPU surfaces). This also fixes a software-drawn view created under a disabled ancestor taking no touches on Android after the ancestor was enabled.
- **Android: empty surface after a rotation:** a GPU surface that was resized after it had drawn (rotating the device, a split-screen resize) drew every later frame into an offscreen framebuffer and stayed empty, also after rotating back. SkiaSharp's `SKGLTextureViewRenderer` rebuilds its render target on the framebuffer that is bound at that moment, which Skia leaves at one of its own after drawing offscreen (the GPU warm-up, layers, filters); `SkUiGlTextureView` rebinds the window's framebuffer first.
- **Centered text in fonts with a line gap:** the font's line gap (hhea / typo line gap) is split above and below each line's glyphs, as CSS and Skia's paragraph place it, instead of all of it going under them. A single line centered in a button, chip or badge, or with `VerticalTextAlignment="Center"`, no longer sits high by half the gap (about 3 pt in a 16 pt button in a font whose gap is a quarter of its size). Line heights and measured sizes do not change; top-aligned text in such fonts starts half the gap lower. Fonts without a line gap (Roboto, SF, Segoe UI, Open Sans) draw as before. Both label layers, spans, HTML and text input (#61).
- **The dim press on light buttons:** `DefaultSkUiLook`'s `Dim` press (iOS, Mac Catalyst, Windows and the default look) darkened nothing on a white, light or transparent button: a white fill faded to 75 % over a white page stays white. A light or mostly see-through fill now darkens under the tint pressed content gets with `ShowsPressEffect`, clipped to the button's corners; dark and colored fills still fade by a quarter (#62).

### Other

- **Demo: search page.** "Search demos", the top row of the flyout (with a magnifier icon), finds any component demo or page as you type (every word must match the control type, title, category or the MAUI control it replaces); Enter opens the first result.
- **Demo: resizable preview area.** Every component page has a `SkUiGridSplitter` under its previews; the area starts as tall as the control plus a margin (short for a check box, tall for a scroller) and at most 60% of the page, so the editors stay in view on phones.
- **Dependencies:** SkiaSharp 4.154.0 (was 4.153.1), HarfBuzzSharp 14.2.1.400.

## 1.2.0

### New features

- **`CascadeInputTransparent` and `IsClippedToBounds` on drawn containers:** MAUI's names on the layouts, the content views, the scroll, swipe, refresh and indicator views, the radio button and the expander, and on the Core containers (`SetCascadeInputTransparent`).
  - `CascadeInputTransparent="False"`: an input-transparent container lets pointers through itself only. Its children still take taps, hover and keyboard focus, and its own recognizers, tooltip and scrolling (by drag, wheel or keys) stay off. The default, `true`, works as before: the whole subtree lets pointers through.
  - `IsClippedToBounds` is the same property as `ClipToBounds`.
- **`Switch.OffColor`** (MAUI 10) on `SkUiSwitch` and `SkUiCoreSwitch`: the track color while off, in every look. `null`, the default, keeps the color scheme's off track.
- **`CheckBox.Command` / `CommandParameter`** (MAUI 10) on `SkUiCheckBox` and `SkUiCoreCheckBox`: the command runs when `IsChecked` changes, from a tap or from code, after `CheckedChanged`. While it cannot execute, the check box looks and acts disabled.
- **MAUI's small members:**
  - `StrokeDashPattern` (read-only) on shapes and borders, both layers.
  - `IsOpaque` on `SkUiImage` and `SkUiImageButton`: accepted for MAUI markup, with no effect on drawing.
  - `Padding` on `SkUiIndicatorView`, `SkUiCoreIndicatorView` and `SkUiRefreshView`.
  - The read-only bindable properties MAUI triggers use: `IsPressedProperty` on `SkUiButton` and `SkUiImageButton`, `IsLoadingProperty` on images (after a load that finished without a dispatcher, on the view's next change), `IsDraggingProperty` on `SkUiCarouselView`.
  - `SkUiCollectionView.UpdateSelectedItems`: replaces the selection in one change.
- **MAUI's gesture recognizers on drawn views:** `SwipeGestureRecognizer`, `PanGestureRecognizer` (one touch point), `PinchGestureRecognizer` and `PointerGestureRecognizer` in a drawn view's `GestureRecognizers` now run in the gesture arena, with MAUI's events, commands and argument types and the view as the sender.
  - `TapGestureRecognizer` runs for any `NumberOfTapsRequired` and for `Buttons="Secondary"` (mouse, pen, trackpad), on views and label spans; a press with a button no recognizer wants is left to the ancestors.
  - Pointer recognizers take entered / moved / exited from hover and pressed / released from presses. `GetPosition` works for the view and other drawn elements on the same surface; `GetPosition(null)` is `null`.
  - Drag and drop recognizers are still not run and are reported once as a `Trace` line, as before.
  - The demo's component gallery has a page with the recognizers on a drawn and a native view side by side.
- **The collection view's and carousel's MAUI shape:**
  - `ItemsLayout` on `SkUiCollectionView` (`LinearItemsLayout` / `GridItemsLayout`, `"VerticalGrid, 2"`) and `SkUiCarouselView` (`LinearItemsLayout`, `"HorizontalList"`): once set, it decides the list's orientation, span and spacings (the carousel's orientation, spacing and snap points), following the layout object's changes. `Orientation`, `Span` and the spacings keep their own values and apply again when it is cleared; setting both is reported once.
  - `ItemSizingStrategy="MeasureFirstItem"` on `SkUiCollectionView`: the first row measured sizes every row.
  - MAUI's `ScrollTo(index, groupIndex, position, animate)` / `ScrollTo(item, group, …)` on `SkUiCollectionView`, and `ScrollToRequested` on both views.
  - The items layout's snap points on `SkUiCollectionView`: `SnapPointsType` (`Mandatory`, `MandatorySingle`) and `SnapPointsAlignment` end drags, flings and wheel scrolling on a row lined up with the viewport's start, center or end, or at either end of the list (a header or footer stays reachable), in lists and grids of both orientations. The fling's end is chosen as it starts and a render-thread spring runs to it: nothing re-records.
  - `ItemsUpdatingScrollMode` on both views. On the collection view: `KeepItemsInView` (default, as before: what shows stays in place), `KeepScrollOffset` (the offset stays, the items move), `KeepLastItemInView` (scrolls to the end after each change). On the carousel: `KeepItemsInView` keeps the current item, as before (MAUI's handlers return to the first item), `KeepScrollOffset` keeps `Position`, `KeepLastItemInView` moves to the last item.
  - `HorizontalScrollBarVisibility` / `VerticalScrollBarVisibility` on `SkUiCarouselView`. `Default` shows none, as before, and a looping carousel never shows one, as in MAUI.
  - `Header="Contacts"`, `Footer` and `EmptyView="No results"` take text in XAML, as on MAUI (a label; the empty view's centered), and the carousel's `EmptyView` too, through `SkUiTextViewTypeConverter`. The properties keep their type (`ISkUiView`); a data header converts to a template bound through the list's context (Migration.md).

- **`IndicatorTemplate` and `IndicatorLayout` on `SkUiIndicatorView`:** MAUI's template makes a drawn view per indicator in a stack (4 DIPs apart, centered, along `Orientation`). Each view is bound to its item (its index without `ItemsSource`), takes `IndicatorColor` / `SelectedIndicatorColor` as its background and goes to the `Selected` visual state while current; a tap selects it. A drawn layout of the app's set as `IndicatorLayout` is shown as it is. Drawing through the look stays the cheaper path.
- **`SafeAreaEdges` (MAUI 10) on drawn containers:** layouts, content views (borders, scroll views, swipe item views), swipe and refresh views take MAUI's property. It is opt-in: every drawn container defaults to `None` and goes edge to edge, as before (MAUI's layouts default to `Container`; set `SafeAreaEdges="Container"` for its behavior). A drawn layout or content view that is a surface root pads its content by how far the window's bars, notch and home indicator reach into it on each edge it keeps clear, and by the soft keyboard with `SoftInput` (iOS and Mac Catalyst). Drawn views inside a surface accept it and ignore it; swipe and refresh views do not apply it.
- **The migration checker converts:** `check_xaml.py --fix` rewrites, in place, `{TemplateBinding X}` and `RelativeSource TemplatedParent` in templates of drawn controls to `RelativeSource AncestorType`, data headers (`Header="{Binding Info}"` with an inline template) to a template bound through the list's context, and the platform-specifics that have a drawn member (iOS `Entry.CursorColor`, Android `Entry.ImeOptions`, iOS picker `UpdateMode`) to that member inside `OnPlatform` (`--all-platforms` for the plain value). It reports other platform-specifics on drawn views as ignored, and no longer reports `ItemsUpdatingScrollMode`, `IndicatorTemplate` or snap points.

### Fixes

- **Android: a drawn view as Shell's flyout content draws again.** Shell puts the flyout content's native view straight into a `CoordinatorLayout`, which never measures or arranges the drawn root, so the flyout stayed blank and let touches through to the page. A drawn surface whose native view gets laid out at a size MAUI did not arrange it to now lays its tree out at that size, as MAUI's own layout views do.
- **A container measured while hidden measures its children once shown.** MAUI's layout managers skip collapsed children, so a layout measured while an ancestor was hidden had no room for them. Showing the ancestor kept that measure (only the recording stays valid). This showed as an empty popup when it was sized before it was shown.

### Other

- The demo's (?) help bubbles show their text again: the bubble is shown before it measures its text.
- The demo's component galleries and pages title each page by its control and what it is for ("SkUiCollectionView: main features vs MAUI", "SkUiCollectionView: groups, grid, horizontal"), so controls with several pages no longer show a column of identical names.
- `SkUiImage` raises `PropertyChanged` for `IsLoading` only when it changes (it was raised with every load state update).
- **Stable releases come from `devel`:** the publish workflow's bump `release` on `devel` makes the stable release there (the next minor straight from a stable version, `1.1.0` → `1.2.0`, or the end of a prerelease line) and moves `master` to it in the same push, so `master` no longer needs merging back after a release. Hotfixes still go to `master`, and a new workflow merges them into `devel`, resolving the changelog and version itself ([docs/Releasing.md](docs/Releasing.md#hotfixes)).

## 1.1.0

### Breaking changes

- **Mac Catalyst 17.0 minimum:** SkiaUi.Maui and SkiaUi.Maui.CommunityToolkit target Mac Catalyst 17.0 (macOS 14) or newer, up from 15.0, because the Mac Catalyst workload that builds with Xcode 27 refuses lower minimums. Apps set `SupportedOSPlatformVersion` for `maccatalyst` to `17.0` or higher. iOS stays at 15.0.
- **Xcode 27 builds need the UIKit scene lifecycle:** iOS 27 closes apps built with Xcode 27 that don't use it. Each app adds a `SceneDelegate : MauiUISceneDelegate` on iOS and Mac Catalyst and a `UIApplicationSceneManifest` in each `Info.plist` that names it ([migration guide](docs/Migration.md#ios-and-mac-catalyst-scene-lifecycle)). The library itself needs no change.

### Fixes

- **Showing a view again no longer re-records what it holds:** MAUI 10.0.120 invalidates the measure of every descendant whose effective visibility changes when a view is shown or hidden, and drawn views measured and recorded again for it (a swipe view's items each time it opened). A drawn view now ignores that invalidation: its size and drawing are unchanged, and the view shown or hidden lays itself out again.

### Other

- **Built with MAUI 10.0.120 and Xcode 27:** SkiaUi.Maui now references MAUI 10.0.120 and builds with .NET SDK 10.0.402. iOS and Mac Catalyst builds work with Xcode 26.6 (workload set 10.0.401) or Xcode 27.1 (workload set 10.0.402.1). iOS 27 closes apps built with Xcode 27 that do not use the UIKit scene lifecycle. The demo, samples, benchmark and device-test apps now use it: a `SceneDelegate : MauiUISceneDelegate` on iOS and Mac Catalyst and a `UIApplicationSceneManifest` in each `Info.plist`. The Mac Catalyst minimum rises to 17.0 (see Breaking changes). CI builds the Apple targets with both Xcode versions (Xcode 27.1 on the `xcode-27` image, Xcode 26.6 on `macos-26`), and runs the device tests and packs on `xcode-27`.
- **Development moved to `devel`:** pull requests target the `devel` branch, which publishes the `1.1.0` prereleases; `master` holds stable releases ([docs/Releasing.md](docs/Releasing.md#branches-and-versions)). The README, roadmap, contributing guide and security policy describe the stable state.
- **Package README:** the readme on nuget.org no longer calls SkiaUi a preview (1.0.0 shipped with the prerelease notice). It now says who SkiaUi is for, what it adds beyond MAUI and which controls it has, and its quick start shows a collection view loading behind a shimmer.

## 1.0.0

### New features

- **Align stack, for bars whose title stays centered:** `SkUiHorizontalAlignStackLayout` and its Core twin `SkUiCoreHorizontalAlignStackLayout` place children by their horizontal alignment, not their place in the list ([SkUiHorizontalAlignStackLayout.md](docs/controls/SkUiHorizontalAlignStackLayout.md)).
  - `Start` children are stacked from the start side, `End` children from the end side, and `Center` children in a row placed by `CenterStrategy` (`SkUiCenterStrategy`): `Parent` (default; centered in the layout, moved aside only to clear the sides), `AvailableSpace`, `ParentOrAvailableSpace`, `AvailableSpaceWhenBothSides`. `Fill` children (the default `HorizontalOptions`) join that row and stretch it across the room between the sides, sharing the extra width (a search field between a back and a menu button).
  - The sides are measured first and the centered children get the width left, so a long title truncates instead of overlapping them. `Spacing`; mirrored right to left.
- **Pickers docked at the bottom, as iOS's:** `PopupPlacement="BottomPane"` on every picker (and their Core twins) docks the popup to the window's bottom edge, edge to edge, with a toolbar on top ([SkUiPicker.md](docs/controls/SkUiPicker.md#the-bottom-pane)).
  - The pane is as wide as the window and reaches its bottom edge; its content pads itself by the safe area (the home indicator, a landscape notch). It is as tall as its content (at most `MaxPopupHeight`), leaves the page undimmed and stays open while the page scrolls.
  - The toolbar holds the title (centered in the pane whatever the sides hold), a **close button** (×, drawn by the look: new `SkUiLook.DrawPopupCloseButton` / `PopupCloseButtonPainter`; it accepts what the pane shows, and screen readers read it as `AcceptText`, else the new `SkUiStrings.DoneText`, "Done"), and Cancel (`UpdateMode="WhenFinished"`) and Clear (`IsPopupClearButtonVisible`) at the start side. Lists, several choices, and the multi-column, date and time pickers' wheels all get it.
  - With `IosSkUiLook` (new `SkUiLook.PickerPaneShowsWheel`), a list to choose one item from shows as one wheel: the item in the middle row is chosen as the wheel turns (a draft until closed with `WhenFinished`), and the close button chooses the item it shows, also when nothing was chosen yet. Other looks keep the list in the pane.
  - Presenters: `SkUiListPopupRequest.SetSelectedIndex(index)` chooses while the popup stays open (applied at once, or the draft `Accept()` takes), for UIs of their own that work like a wheel. `SkUiToolkitPopupPresenter` shows panes square at the window's bottom edge (aligned to its popup page's bottom, since that page is inset by the safe area on iOS); it no longer passes an all-zero margin, which the toolkit replaces with its default of 30.
- **Pickers with their own UI:** derive a picker and show a UI of your own for its items ([SkUiPicker.md](docs/controls/SkUiPicker.md#popups-on-your-popup-system)).
  - `SelectItemsAsync(selection, cancellationToken)`, a new protected virtual on `SkUiPicker` and `SkUiCorePicker`: called when the picker opens with what to choose from (new `SkUiPickerSelection`: `Items`, `Texts`, `SelectedItems`, `AllowsMultiple`, `IsItemEnabled`, `Title`, `PopupRequest`); it returns the chosen items (none: clear; `null`: dismissed). The picker applies them with its own rules and events; by default the drawn list on the presenter.
  - `ShowPopupAsync(request, cancellationToken)`, a new protected virtual on `SkUiPickerBase` and `SkUiCorePickerBase` (every picker, wheels and dates too): shows the popup with the presenter's contract and typed requests, by default on the picker's presenter; the base shows the requests an override does not handle.
- **Picker wheels for screen readers:** in the popups of `SkUiMultiColumnPicker`, `SkUiDatePicker`, `SkUiTimePicker` and `SkUiDateTimePicker` (and their Core twins) each wheel is one adjustable element, as a native wheel picker's column: named by MAUI's `SemanticProperties.Description` set on its `SkUiPickerColumn` (new `SetSemanticDescription` / `SetSemanticHint`), else its `Header`, and the date and time wheels by `SkUiStrings`' `DayText` … `SecondText` also without headers shown; its value is the middle row's item and its place ("10, 2 of 12", new `SkUiStrings.WheelPositionFormat`). Increment and decrement (VoiceOver and TalkBack swipes, Narrator's range value) step to the next or previous item that can be chosen and choose it, following the date's rules; the wheels' rows are no longer elements of their own.
- **MAUI's child APIs on drawn layouts:** code-behind that builds a `Grid`, a stack or another layout ports by renaming the type.

- **App-level implicit styles on drawn controls:** a `Style` for a drawn control in `Application.Resources` (implicit, or one for a base type with `ApplyToDerivedTypes`) crashed the control's construction with a `NullReferenceException` (labels, buttons, text fields, pickers, steppers, shapes, borders, images, avatars, scroll and collection views, …), or was silently undone, so the control drew its defaults. MAUI applies such a style inside its base `View` constructor, before the control's own constructor runs. Every drawn control now has the state its property callbacks use ready before that (field initializers, or engines and parts created on first use), and a constructor that starts a field from a default keeps a value a style already set. `ClipToBounds` defaults of swipe, refresh and shrink layouts and the avatar's centering no longer hide a style's value.
  - A picker's `SelectedIndex` set by a style after its `ItemsSource` is no longer hidden by the picker's own reconciliation.
- **Image loads finishing without a dispatcher:** a load started where there is no dispatcher to return to (headless tests, a tree built off the UI thread) finished on the thread pool while the image was still in use on its own thread. This affected drawn images, image buttons, slider thumbs and avatars on both layers. A new source set as one finished threw `ObjectDisposedException` (a disposed `CancellationTokenSource`), or raised `LoadingFinished` twice. A reload finishing during a paint disposed the image being drawn: an avatar arranged larger than expected drew no image, or crashed the process. A finishing load now waits for the image's current call (a new source, placeholders, painting) and applies its result after it.

### Other

- **Styling Core nodes:** a docs section (style methods, factory methods, the look and the color scheme in place of MAUI styles) in [SkUiCore.md](docs/controls/SkUiCore.md) and the "Styles for Core nodes" sample.

### New features

- **Text that fits (C3):** labels fit their text to their size, on `SkUiLabel` and `SkUiCoreLabel`, inherited by buttons ([SkUiLabel.md](docs/controls/SkUiLabel.md#shrink-to-fit)).
  - `ShrinkToFit` and `MinimumFontScale` (default 0.5): text that does not fit is drawn smaller, down to the minimum scale. It does not fit when a line would be truncated, lines are past `MaxLines`, word wrap would break a word inside, a `NoWrap` line is wider than the label, or the lines are taller than it (a `HeightRequest`, a fixed grid row). Words that wrap whole keep the size.
  - `AllowsTightening`: up to 0.05 em less space after each character before the text is truncated or shrunk (as iOS's `allowsDefaultTighteningForTruncation`).
  - `GrowToFill` and `MaximumFontScale` (default 2): text with room is drawn larger, as large as still fits (as Android's uniform auto-size).
  - Every font size and character spacing scaled alike, also of spans and HTML; as little as needed (quarter-DIP steps). Text still too long is broken by `LineBreakMode` at the minimum; a custom `LineBreaker` shortens what still does not fit there.
  - Measured for the space offered, drawn for the slot arranged; free when off, and a few layouts when the text or the space changes (the fit is remembered for measure and draw).
  - Demo page **Label** (all five properties); the samples app's **Text that fits** has a headline that tightens and shrinks and a year that grows.
- **Refresh view (C2):** `SkUiRefreshView` is MAUI's `RefreshView` around drawn content: its XAML ports by changing the prefix ([SkUiRefreshView.md](docs/controls/SkUiRefreshView.md)).
  - `IsRefreshing` (two-way), `Command` / `CommandParameter`, `RefreshColor`, `IsRefreshEnabled` and `Refreshing`, with MAUI's rules: `IsRefreshing` stays `false` while the view is disabled, the pull is off or the command cannot execute; disabling the view or turning `IsRefreshEnabled` off ends a refresh.
  - A drag in a vertical drawn scroller of the content (`SkUiScrollView`, `SkUiVirtualScrollView`, `SkUiCollectionView`, Core scroll views) pulls at its top, also on short content, with overscroll off, and after the same drag scrolled it to the top; with nested scrollers the outermost one under the finger. Elsewhere (content without a scroller, a header above a list) the view itself pulls, while the content's scroller is at its top.
  - The collection view's drawn indicator, shared: it follows the pull at composite time and spins on the render thread while refreshing. Taps in the content keep working; nested refresh views pull for themselves; a scroller that left the content and the view keep each other alive in neither direction.
  - One indicator for every pull-to-refresh, public as `SkUiCoreRefreshIndicator` (`RefreshIndicator` on both controls; usable on its own with `PullProgress` / `IsRefreshing`) and drawn by the look: `SkUiLook.DrawRefreshIndicator` / `RefreshIndicatorPainter` (default: the look's activity indicator on a badge), `RefreshIndicatorSize`, `RefreshTriggerDistance`, `RefreshRestDistance`, `RefreshIndicatorSpinPeriod`, `GetRefreshPullFeedback`, `GetRefreshIndicatorShadow`, `RefreshIndicatorDrawsPullProgress`.
  - `RefreshStyle` on both controls: `Overlay` (a badge over the content) or `Inline` (iOS: the content moves down with the pull and stays down while refreshing); `Default` follows the look, and `DefaultSkUiLook.RefreshStyle` the platform (inline on iOS and Mac Catalyst).
  - `RefreshTriggerDistance` on both controls; `IsMousePullEnabled` (mouse drags pull only when set: touch and pen always do).
  - `RefreshCompletion="Automatic"` on both controls: the control sets `IsRefreshing` back when the refresh's work is done (a command that is busy while it runs, such as the MVVM Toolkit's `AsyncRelayCommand`, and deferrals taken in `Refreshing` with `SkUiRefreshingEventArgs.GetDeferral()`). `Manual` (default) keeps MAUI's rule.
  - Pointers report their device: `SkUiTouchEvent.Device` and `SkUiPointer.Device` (`Touch`, `Mouse`, `Pen`) on every platform.
  - Demo page **RefreshView** (next to MAUI's, with the style, trigger, mouse and completion editors); leak scenario `RefreshPulled`. The migration guide and skills map `RefreshView` around drawn content to it; `check_xaml.py` reports a collection view with its own pull-to-refresh inside an `SkUiRefreshView`.
- **Overscroll events (C2):** `SkUiScrollView` and `SkUiCoreScrollView` report pulls past their edges, for effects and gestures of the app's own: stretchy headers, pull to dismiss, pull to load the next page ([SkUiScrollView.md](docs/controls/SkUiScrollView.md)).
  - `Overscrolled` with `OverscrollX` / `OverscrollY` and `IsDragging`, while dragging, bouncing and springing back (reported each frame from the render thread; one reused arguments object, no allocation per frame); `OverscrollX` / `OverscrollY` properties.
  - `PullReleased` with the edge and the distance when a drag is released past an edge.
  - `PullEdges` (`SkUiScrollEdges` flags): edges a drag can pull past also when the content does not overflow or `Overscroll` is `None`. Physical edges, also in right-to-left layouts.
  - The **ScrollView** demo page shows the overscroll and the last release, with a `PullEdges` choice.

- **Swipe view (C1):** `SkUiSwipeView` is MAUI's `SwipeView` on the drawn surface: its XAML ports by changing the prefix ([SkUiSwipeView.md](docs/controls/SkUiSwipeView.md)).
  - `LeftItems` / `RightItems` / `TopItems` / `BottomItems` take MAUI's `SwipeItems` and `SwipeItem`s, drawn as MAUI's handlers show them (background, icon above text, white or black text by the background); `SkUiSwipeItemView` replaces MAUI's `SwipeItemView` (native views) with drawn content, `Command` / `CommandParameter` / `Invoked`, disabled while its command cannot execute.
  - Sizes, open distance and `Threshold` (default 60 %) as MAUI's handlers; `SwipeMode.Reveal` opens past the threshold or on a fast swipe, `SwipeMode.Execute` invokes the first visible item (its icon and text at the inner edge, next to the content, so a short swipe shows them); an invoked item closes the view unless `SwipeBehaviorOnInvoked` is `RemainOpen`. A drag past the closed position reveals the other side of the axis.
  - `SwipeStarted` / `SwipeChanging` / `SwipeEnded` (MAUI's argument types), `Open(OpenSwipeItem, animated)` / `Close(animated)`, and a read-only bindable `IsOpen`.
  - In lists: the swipe takes horizontal drags and leaves vertical ones to the scroller (inner drags, such as a slider's, win); a tap on open content closes it without reaching the content; a scroll around an open view and a new binding context (a recycled row) close it; the list's item taps and selection keep working.
  - The content and the items move at composite time (nothing re-recorded while swiping or settling); a side's items are created when first revealed; items and collections shared through resources keep no view alive.
  - Demo pages **SwipeView** and **SwipeItemView** (next to MAUI's), **CollectionView with SwipeView rows**; leak scenario `SwipeViewsSwiped`. - **Collection view groups, grids and horizontal lists (B3, FR-22):** `SkUiCollectionView` lays out rows of a row model over the B1 engine; every source or group change becomes the smallest change of the rows ([SkUiCollectionView.md](docs/controls/SkUiCollectionView.md)).
  - Groups: `IsGrouped` (MAUI's shape: each group the list of its items; group and item changes followed), `GroupHeaderTemplate`, `GroupFooterTemplate`; `ScrollToGroup`; `ScrollToItem(item, group)` for an item shown in several groups; `ItemTapped` reports the item's group.
  - Expandable groups: `AllowGroupExpandCollapse` (a tap on a header), `ExpandGroup` / `CollapseGroup` / `ExpandAll` / `CollapseAll`, cancelable `GroupExpanding` / `GroupCollapsing`, `GroupExpanded` / `GroupCollapsed`, `AutoExpandGroups`, and `ISkUiExpandableGroup` for groups that keep their own state. Collapsed items are not realized; what shows stays in place; headers go to the `Expanded` / `Collapsed` visual state; scrolling to an item of a collapsed group expands it.
  - Sticky group headers (`IsStickyGroupHeader`): the current group's header stays at the start, pushed away by the next one (moved by a translation, rebound only when the group changes); scrolling to an item lands after it.
  - Grids: `Span` items per row (as tall as the tallest), `SpanSpacing`; grid rows are recycled whole and their cells pooled per template.

  - Loading more: `LoadMoreMode` (`Manual` with a load-more row, `Auto`, `AutoOnUserScroll`), `LoadMorePosition` (`End`, `Start` keeping what shows while older items are inserted), `LoadMoreCommand`, `LoadMoreTemplate`, two-way `IsLoadMoreActive`, `LoadingMore`, `LoadMoreText`.
  - Indices count items across groups; `RemainingItemsThreshold` counts rows.
  - `KeepSelectionVisible`: on selection changes, size changes (rotations) and the first layout the list scrolls as little as needed to show the selection: a single selection fully; a multiple selection as many selected items as fit around the item last selected by a tap, else from the first selected item (changes made by the app or a binding). Taps do not move the list away from the finger; removing items does not scroll.
  - Demo page **CollectionView (groups, grid, horizontal)** next to MAUI's; leak scenario `CollectionViewGrouped`. The migration guide and skills map grouped, grid, horizontal and multiple-selection lists to `SkUiCollectionView`; `check_xaml.py` maps `ItemsLayout` to `Orientation` / `Span` / spacings, and the audit counts only reorderable lists and lists with snap points as blocked.
- **Collection view (B2, FR-22):** `SkUiCollectionView` is a drawn, virtualized list on the B1 engine, with SkiaUi's own API (not a MAUI rename; [SkUiCollectionView.md](docs/controls/SkUiCollectionView.md)).
  - `ItemsSource`, `ItemTemplate` (or a selector; the element's XAML content), `ItemSpacing`, `ItemExtent`, `EstimatedItemSize`; items of any height, recycled per template.

Item containers can show the press effect (`ShowsItemPressEffect`); screen readers read the selected item as "Selected" (`SelectedStateText`).

  - Pull-to-refresh: `IsPullToRefreshEnabled`, two-way `IsRefreshing`, `RefreshCommand` (+ parameter), `RefreshColor`, `Refreshing`. A drawn indicator follows the pull without re-recording and spins on the render thread; the pull works on short lists and without overscroll. As MAUI's `RefreshView`, setting `IsRefreshing` runs the command.

- **Virtualized lists (B1, FR-21):** `SkUiVirtualVerticalStackLayout` is a vertical stack whose item views are created only near what its scrollers show, and `SkUiVirtualScrollView` is a vertical scroll view of one, for plain lists ([SkUiVirtualVerticalStackLayout.md](docs/controls/SkUiVirtualVerticalStackLayout.md)).
  - Items from `ItemsSource` + `ItemTemplate` (a `DataTemplateSelector` chooses per item; `INotifyCollectionChanged` inserts, removes, moves and replacements touch only their items; the source is listened to weakly), or from `ItemFactory` by index, endless until it returns `null` or with `ItemFactoryCount`.

When items before the first visible one change height, what shows stays in place (scroll anchoring), also during a fling.

  - The template is created when the content loads, so `ContentLoading="WhenShown"` defers it too; `ContentTemplate` runs only once the template has a presenter (a template without one logs a `SkiaUi:` trace line). ### Breaking changes

- `SkUiCollectionView.Refreshing` is an `EventHandler<SkUiRefreshingEventArgs>` (for `GetDeferral()`). Lambdas and handlers taking `EventArgs` still attach; only delegates stored as `EventHandler` need the new type.
- `SkUiCollectionView`'s pull-to-refresh no longer reacts to mouse drags; set `IsMousePullEnabled="True"` to keep it on desktop (touch screens and pens pull as before).

### Fixes

- **Symbols from fallback fonts no longer make lines taller:** a glyph from a fallback font (☆ comes from Hiragino Sans on macOS and iOS, whose leading is half its size) extends a line only by its own height, without that font's leading. A button with "☆ Star" is as tall as one with "Star", and its text stays centered.
- **Hosted controls measure again once they have a native view:** `SkUiMauiContentView` measures its control again when the control gets its platform view. A hosted `SearchBar` now takes its own native height and needs no `HeightRequest`. On iOS and Mac Catalyst 26, a height below the native one shrinks only the bar's background, not its field.

### Other

- **Drawn controls release their native objects themselves:** labels, buttons and radio buttons no longer keep a Skia font and paint each: fonts are shared by typeface, size and style, and text draws with one shared paint, so 1,000 labels allocate about 440 KB less and are measured faster the first time. Text blobs are disposed when a layout replaces its lines, when a control leaves its drawn parent and when its surface is torn down, and the compositor disposes committed clip paths, content clips and shadow outlines when a control is removed or the surface goes (not only when a change replaces them), instead of the finalizer thread (whose disposals contend with drawing): a page of 1,000 buttons leaves no Skia object to it. `scripts/bench.sh --quiet-gc` compares code paths without garbage collections moving between phases ([Benchmarks.md](docs/design/Benchmarks.md)).
- **Scroll corrections reach render-thread motions:** a scroller's offset can be corrected while a fling, animated scroll or snap runs on the render thread (content before the viewport changed size): the correction travels with the frame that brings the new layout and the motion continues from it, instead of being stopped.
- **Layout converges within a frame:** a surface root whose relayout invalidates layout again (a virtual list realizing items for its new viewport) is laid out again before the frame, up to three passes.
- **Contacts sample:** the samples app's **Contacts** page is now a full contacts screen on `SkUiCollectionView`: a live grouped list over the contacts (filter, sort and grouping followed item by item; a contact may be in several groups), search, grouping by letter or by group (starred, family, business) or none, rows or tiles, photos (MIT-licensed portraits), a preview beside the list on wide screens or in a popup on phones, a selection mode on long press (checkboxes, three-state group headers, select all, star, groups, delete) and a form to add contacts with a photo from the gallery. Samples can now fill the page below their description and show several source files.

- **MAUI visual states (P2)** on every `SkUi*` view, from SkiaUi's own input state: `Disabled` (also while a button's command cannot execute), `PointerOver`, `Normal`, and `Focused` / `Unfocused` in a focus group, plus each control's MAUI states: `Pressed` on `SkUiButton` / `SkUiImageButton`, `IsChecked` on `SkUiCheckBox` (when the `CommonStates` group defines it, as in MAUI), `On` / `Off` on `SkUiSwitch`, `Checked` / `Unchecked` on `SkUiRadioButton`. Checked against MAUI's controls step by step. `StateTrigger`, `CompareStateTrigger` and `AdaptiveTrigger` work on drawn controls.
  - **Hover:** new `SkUiView.IsPointerOver` and `SkUiTouchAction.HoverMoved` / `HoverExited`. A mouse, trackpad, pen or iPad pointer over the surface makes the view under it and its ancestors pointer-over. Windows reports hover through SkiaSharp; Android surfaces use the view's `Hover` event, Apple surfaces a `UIHoverGestureRecognizer` ([EventMechanism.md](docs/design/EventMechanism.md#hover)).
  - Before, only `SkUiButton` raised `Normal` / `Pressed` / `Disabled`.

- **MAUI API parity of existing controls (P1)**, on SkUi* and Core:
  - **Switch:** `IsToggled` (two-way bindable) and `Toggled` (`ToggledEventArgs`), MAUI's names for the two-state view of `CheckState`; they stay in step with `IsChecked`.
  - **RadioButton:** checking one unchecks the rest of its group, with MAUI's rules: siblings in the same parent when there is no `GroupName`, every radio button with the same `GroupName` on the page otherwise. New `Value`, and MAUI's own `RadioButtonGroup.GroupName` / `SelectedValue` work on drawn layouts with unchanged markup: the layout names its radio buttons, and `SelectedValue` binds two-way to the checked one's `Value` ([SkUiRadioButton.md](docs/controls/SkUiRadioButton.md)). `SkUiCoreRadioButton`: the radio buttons in the same parent exclude each other.
  - **Button, ImageButton:** `Pressed` and `Released` events, in MAUI's order (`Pressed`, `Released`, `Clicked`); a cancelled press raises `Released` without `Clicked`.
  - **BoxView:** `SkUiBox` / `SkUiCoreBox` `CornerRadius` (per corner, MAUI's `CornerRadius`).
  - **Line:** `X1`, `Y1`, `X2`, `Y2` and the `(x1, y1, x2, y2)` constructor; the line measures to its far end points plus the stroke and is placed as MAUI places an unstretched `Line` ([SkUiLine.md](docs/controls/SkUiLine.md)).
  - **Image:** `Aspect.Center` (unscaled and centered, also for images the decoder reduced) and plain `http://` sources (they need the platform's cleartext permission).
  - **ImageButton:** `Padding`, `BorderColor` and `BorderWidth`; per-corner `CornerRadii` (with MAUI's `int` `CornerRadius` setting all four, as on `SkUiButton`), which now clip the image and the border as well as the press tint.
  - **Breaking:**
    - `CheckedChanged` on all toggles (both layers) is an `EventHandler<CheckedChangedEventArgs>` (was `EventHandler<bool>`): read `args.Value`.
    - Radio buttons uncheck the other radio buttons of their group (before, `GroupName` was only stored). Apps that cleared siblings in `CheckedChanged` can drop that code.
    - `SkUiCoreRadioButton.GroupName` / `SetGroupName` are removed: a Core group is the radio buttons in one parent.
    - `SkUiLine` / `SkUiCoreLine` draw between their points instead of the diagonal of their bounds; a line without points draws nothing. Set `X2` / `Y2` (e.g. to the old `WidthRequest` / `HeightRequest` minus the stroke) to keep a diagonal.
    - `SkUiImageButton.CornerRadius` and `SetCornerRadius` are `int` (were `double`), as MAUI's `ImageButton`; fractional and per-corner radii go in the new `CornerRadii`.
    - Core labels and buttons have only `CornerRadii`: `SkUiCoreLabel.CornerRadius` / `SkUiCoreButton.CornerRadius` (the `int` view) are removed, `SkUiCoreImageButton.CornerRadius` became `CornerRadii`, and `SetCornerRadius` takes a `double` on all three (sets all four corners).

- **Core attached properties** (`SkUiCoreAttachedProperty<T>`, `node.GetValue` / `SetValue` / `ClearValue` / `IsSet`): typed per-child values that Core layouts read, the Core counterpart of MAUI attached properties ([SkUiCore.md](docs/controls/SkUiCore.md#attached-properties)). Grid cells (`SkUiCoreGrid.RowProperty`, …), absolute bounds (`SkUiCoreAbsoluteLayout.LayoutBoundsProperty` / `LayoutFlagsProperty`) and shrink factors now live on the child instead of in per-layout tables: they can be set before the child is added and stay with it when it moves. The existing layout methods are unchanged and write the same values.
  - `SkUiCoreAbsoluteLayout.Add(child)` is now allowed (it was a compile error): the child is placed by its own `LayoutBounds` / `LayoutFlags`, by default at its measured size at (0,0).
- **`SkUiFlexLayout`:** MAUI's `FlexLayout` API (`Direction`, `Wrap`, `JustifyContent`, `AlignItems`, `AlignContent`; attached `Order`, `Grow`, `Shrink`, `AlignSelf`, `Basis`, the same property objects as MAUI's) laid out by MAUI's `FlexLayoutManager`. MAUI's flex engine is internal, so SkiaUi ships a port of it; frames match MAUI's `FlexLayout`. SkUi* only ([SkUiFlexLayout.md](docs/controls/SkUiFlexLayout.md)).
- **`SkUiWrapLayout` / `SkUiCoreWrapLayout`:** children flow left to right and wrap onto new rows, with `Spacing` between items and `RowSpacing` between rows; children align inside their row. For chips, tags and filter rows ([SkUiWrapLayout.md](docs/controls/SkUiWrapLayout.md)).
- **Shrink stacks** (`SkUiHorizontalShrinkLayout`, `SkUiVerticalShrinkLayout`, `SkUiCoreHorizontalShrinkLayout`, `SkUiCoreVerticalShrinkLayout`): stacks that fit their main axis. On overflow, children shrink by their `SkUiShrinkFactor` (attached `SkUiShrinkLayout.Shrink`; Core `SkUiCoreShrinkLayout.ShrinkProperty`, e.g. `Add(child, SkUiShrinkFactor.Auto)`): `None` (default) keeps its size, `Auto` shrinks in proportion to its natural size when larger than the average child, a number shrinks by factor × natural size as CSS `flex-shrink`; no child goes below its minimum size. A label then truncates or wraps next to fixed icons; otherwise the layout is a plain stack that takes only the space it needs ([SkUiShrinkLayout.md](docs/controls/SkUiShrinkLayout.md)).
- **Fixed:** drawn text (`SkUiLabel`, buttons, Core labels) now finds fonts registered only with MAUI's `ConfigureFonts`, on every platform. MAUI's registrar returns a PostScript name on iOS / Mac Catalyst, an asset file name on Android and an `ms-appx:` / `ms-appdata:` URI on Windows. The fallback only handled file paths, so these fonts fell back to the default font unless the app also called `SkUiFonts.Register`.

- **Retained compositor with a render thread** ([RenderingPipeline.md](docs/design/RenderingPipeline.md)): the UI thread records only the nodes whose content changed; GPU surfaces composite on a render thread. Offset, transform, opacity, clip and scroll offset are composite-time properties (no re-record).
- **Metal on iOS / Mac Catalyst** replaces the deprecated GLKView-based `SKGLView`; Android GPU surfaces render on their own GL thread.

Core nodes gain `FlowDirection`. Demo pages have a shared FlowDirection editor.
